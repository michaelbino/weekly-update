The Weekly Update

Write your school newsletter in Google Docs. Send a polished, phone-friendly email and a matching web page, straight from the Doc's own menu.

How it works

A Google Doc in, a newsletter out

A script attached to the template Doc reads it through the Google Docs API. It turns your headings, text, lists, images and file links into an email that works in Gmail, Apple Mail and Outlook.

Start the issue

Newsletter › Start next issue copies last week's Doc and updates the date.

Write

Edit it like any Doc, together with co-editors, using comments, suggestions and version history.

Publish

Publish web version creates the public page that “View in browser” opens.

Review & send

Send preview to me, check it on your phone, then forward it or paste the HTML into your mailer.

Doc design vs. output

Editors write plain Docs. Readers get a designed newsletter.

No drag-and-drop builder and no HTML. Built-in paragraph styles carry the structure, and the brand colours, fonts, dividers and footer come from the template.

The Newsletter menu

Everything happens inside the Doc

The script adds one menu to Google Docs. Editors never open the script editor, a terminal or another website.

Illustration of the menu. The labels match the script exactly.

Preview
Opens the rendered email at desktop or phone width, with Copy HTML for pasting into any mailer.
Send preview to me
Emails the newsletter to whoever clicked, from their own account, for a final read on a real phone. It also refreshes the web version once that's published.
Send preview to team
The same, sent to a list of reviewers you type in (remembered for next time).
Publish web version
Saves the rendered email as the issue's public page, plus a translated copy for each chosen language. The email's “View in browser” link and 🌐 language row open them, and each issue keeps its own links.
Start next issue
Copies the Doc, suggests “Weekly Update - Week of M/D” as the name (which becomes the subject) and updates the date line.
Settings…
Sender name, reply-to, subject override, inbox preview text, translation languages, colours, background photo, footer and small print. Shared by every issue in the folder.
How to write the newsletter
A sidebar with the weekly routine and the Doc-to-email rules.

The dialogs and sidebars are the script's own HTML templates, rendered outside Google Docs, so Google's window frame is missing.

Make it yours

Change the layout, not just the colours

Editors handle colours, fonts and footer text in Settings. Maintainers can go further in one file, apps-script/Theme.js: override design tokens for size, spacing, corners and dividers, replace any block's HTML template, or add rows above or below the content.

var NEWSLETTER_THEME = {
  tokens:    { cardRadius: '16px', h1Size: 24, dividerStyle: 'dotted' },
  templates: { cardBottom: '<tr><td class="nl-box" align="center">…links…</td></tr>' },
  css:       '.nl-pill a{border-radius:999px}'
};

npm run preview re-renders the sample issue on every save, npm run check-theme catches typos ("Did you mean h1Size?") and broken templates, and CI checks the theme on every push. Prefer the browser? Edit Theme in the Apps Script editor and watch Newsletter › Preview. The theming guide lists every token and template, with email-safe recipes.

Output formats

One Doc, five ways out

Responsive HTML email

Built from tables with inline styles, plus an Outlook wrapper, hidden inbox preview text, a phone layout below 630px and a forced light colour scheme. It stays under the size where Gmail clips long messages (about 100 KB).

Web version

The same design as a public page for “View in browser”. It's a saved copy of each issue, so old emails keep opening their own week.

Translated web pages

For each language in Settings (by default Español, 中文, 한국어, Kreyòl ayisyen and العربية), Google Translate produces a copy of the web page. A 🌐 row at the top of the email and every page links them all.

Right-to-left languages get right-to-left layout. Each page carries a machine-translation notice with a link back to the English original. Translation uses Apps Script's built-in Google Translate: no API key and no billing. Text inside flyer images isn't translated.

Plain-text alternative

Sent with every email for text-only mail apps and screen readers.

Portable HTML for your mailer

Preview › Copy HTML gives standard email HTML you can paste into any mailing tool that accepts custom HTML. Images point to public copies in your Drive, so they keep loading when the email is forwarded.

There's also a command-line tool for maintainers:

node cli/newsletter.mjs render --doc <doc-url> --out out
node cli/newsletter.mjs send   --doc <doc-url>
Trade-offs

Compared with a paid newsletter service

What you gain

  • No subscription or per-seat pricingIt runs on Google Apps Script with the Google account you already have.
  • Nothing new to learnEditors write in Google Docs. There's no new login or builder.
  • Real collaborationCo-editing, comments, suggestions and full version history come with Docs.
  • Your content stays yoursIssues, images and settings live in your Drive, not on a vendor's servers.
  • No lock-inThe output is standard email HTML that works with any sender. The code is MIT-licensed and yours to change.
  • A permanent archiveEvery issue is a Doc plus a web page with a stable link.
  • Translation includedFamilies get one-tap links to Google-translated pages in the languages you choose, at no extra cost.

What it explicitly does not do

  • Manage contacts or mailing listsThere's no audience, subscriber list, groups or sign-up form. Your school's system (Finalsite, your SIS, Google Groups) owns distribution.
  • Send to families in bulkPreview sends go through Apps Script's mail service, which has daily recipient limits meant for previews, not school-wide sends.
  • Handle unsubscribes or complianceOpt-outs, bounces and list-mail rules belong to your sending platform.
  • Track opens or clicksThere's no analytics or tracking pixels.
  • Schedule sendsThere's no send queue. Send from your mail system when you're ready.
  • Human-quality translationTranslations are machine-generated, and text inside images isn't translated.
  • Offer a visual builderLayout comes from Doc styles and one brand template, not drag-and-drop blocks.

In short, this replaces the authoring and design part of a newsletter service. Hand the finished email or its HTML to whatever already delivers mail to your families.

Setup

For the maintainer

You'll need Node 20 (or mise), Docker for tests, and Google's gws CLI signed in with the Drive, Docs, Apps Script and Gmail scopes. Turn on the Apps Script API in your Apps Script settings.

git clone https://github.com/michaelbino/weekly-update && cd weekly-update
scripts/create-template.zsh   # Drive folder, seeded template Doc, bound script, web app
scripts/deploy-script.zsh     # push script changes and redeploy the web app
scripts/test.zsh              # test suite in Docker
scripts/teardown.zsh          # move the template folder to the trash

No command line? Every step also works in Drive, Docs and the Apps Script editor: copy-paste the script files, deploy the web app from the editor's Deploy menu, and validate a theme by running checkTheme. The browser setup guide walks through it.

Then open the template Doc, reload it, and use the Newsletter menu. Google asks you to authorize the script the first time. Brand defaults live in apps-script/Config.js. The README covers the rest.
